# Weather App

Приложение погоды. Пользователь вводит название города и видит текущую
температуру, ощущаемую температуру, влажность, скорость ветра и описание
погоды. Данные берём из API OpenWeather.

Верстаем по макету в Figma. Пишем на чистых HTML, CSS и JavaScript,
без фреймворков и сборщиков.

## Названия классов

Разметку и скрипт пишут разные люди и одновременно. Скрипт ищет элементы
на странице по названиям классов. Если в HTML поле ввода назвали `input-city`,
а скрипт ищет `city-input`, он его не найдёт. Страница откроется, но работать
не будет, и вылезет это только когда начнём всё собирать вместе.

Поэтому названия классов из таблицы ниже обязательны. А структуру разметки,
теги и вложенность выбирает тот, кто её пишет, тут ограничений нет.

| Класс | Что это |
| --- | --- |
| `header`, `header-title` | шапка и заголовок в ней |
| `weather-app` | основной контейнер страницы |
| `search-form` | форма поиска |
| `city-input` | поле ввода города, нужен атрибут `name="city"` |
| `search-button` | кнопка поиска, `type="submit"` |
| `loading` | надпись про загрузку |
| `weather-result` | весь блок с результатом |
| `main-card` | большая карточка сверху |
| `temperature` | температура |
| `city-name` | название города |
| `weather-icon` | иконка погоды, тег `img` |
| `details` | контейнер для карточек снизу |
| `feels-card` | карточка «ощущается как» |
| `detail-title` | подпись внутри карточки |
| `feels-like` | сама ощущаемая температура |
| `other-card` | карточка с остальными данными |
| `humidity`, `wind`, `description` | влажность, ветер, описание погоды |
| `error-card` | блок с ошибкой |
| `error-title`, `error-message` | заголовок и текст ошибки |
| `hidden` | скрывает элемент, `display: none` |

Блоки `loading`, `weather-result` и `error-card` при открытии страницы
не видны, на них сразу стоит класс `hidden`. Скрипт снимает и возвращает
его по ходу работы.

Скрипты в `index.html` подключаем в таком порядке:

```html
<script src="./config.js" defer></script>
<script src="./index.js" defer></script>
```

В `config.js` объявлена константа `APP_ID`, в `index.js` она используется.
Если поменять порядок, скрипт про неё не узнает и упадёт.

Название кажется неудобным, скажи до того, как начал. Потом переделывать
придётся всем сразу.

## Ключ от API

Ключ у каждого свой и в репозиторий не попадает, чтобы не светить его
на публике. Заводим локально:

```bash
cp config.example.js config.js
```

Дальше открываем `config.js` и вставляем свой ключ вместо заглушки.
Берётся он бесплатно на <https://openweathermap.org/api>, в разделе
«My API keys» после регистрации. Свежий ключ начинает работать не сразу,
иногда нужно подождать до часа.

`config.js` записан в `.gitignore`, так что случайно закоммитить ключ
не получится.

## Как работаем

В `main` напрямую не коммитим, только через Pull Request.

```bash
git switch main
git pull
git switch -c feature/название-задачи
```

Поработали, дальше:

```bash
git add .
git commit -m "Короткое описание на английском"
git push -u origin feature/название-задачи
```

После пуша на GitHub появится кнопка «Compare & pull request». Жмём,
назначаем ревьюера, ждём. Свой PR сами не мержим.

Перед каждой новой веткой обязательно делаем `git pull` в `main`, иначе
будешь писать поверх устаревшего кода. Если `git pull` ничего не тянет,
проверь `git branch -vv`, скорее всего стоишь не на той ветке.
